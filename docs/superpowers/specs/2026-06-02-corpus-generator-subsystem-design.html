00Problem

The phase-classifier training plan put a ground-truth corpus schema and timeline metrics into the test harness, but there is no way to generate synthetic corpus data at scale. Today Corpus/synthetic/ is empty; only hand-written fixtures exist. Without a generator, config-tuning and (later) a learned model have nothing to chase. This subsystem is parent-spec §3: a dev-time CLI that emits synthetic CorpusCase JSON with exact, free boundary truth.

01Goals & non-goals

Goals

  1. Generate schema-valid synthetic cases the existing harness loads and scores with no harness changes.
  2. Author each case one phase block at a time → boundary truth exact by construction (§3b).
  3. Share the schema between CLI and harness via a single source of truth (no drift).
  4. Seed realistic style from real labeled transcripts when available; degrade to zero-shot.
  5. Keep it dev-time only — never shipped, never per-CI, no network in unit tests.

Non-goals

  • TTS / synthetic audio (classifier reads transcripts).
  • Full archetype library, full ambiguity distribution, bulk generation — follow-up plans.
  • Converting the two real labeled files into Corpus/real/ cases — free later, off the critical path.
  • Editing features.json (project rule).

Single source of truth. TrancePhase + corpus DTOs move into CorpusKit, added to Ilumionate.xcodeproj as a local package dependency and linked to the app (Ilumionate), IlumionateTests, and LumeLabel. Old Ilumionate/TrancePhase.swift and IlumionateTests/Corpus/{CorpusCase,CorpusLoader}.swift are deleted and replaced with import CorpusKit. The app keeps its typealias Phase = TrancePhase shim so the 8 referencing files do not churn.

⚠ Risk — Xcode package linking. Linking a local SwiftPM package into Xcode targets is the one mechanical risk (synchronized groups / target membership). Mitigation: make the extraction + linking the first plan task, gated by a green xcodebuild -scheme Ilumionate build and a green IlumionateTests run before any generator logic. Fallback (non-preferred): keep TrancePhase in the app and bridge predicted-vs-truth by rawValue — reintroduces drift.

04Generator internals

Assembles a session one phase block at a time, so boundary truth is exact and free.

  • PhasePlan — template + variation. Ordered [(phase: TrancePhase, durationSec: Double)]. Tracer bullet ships one archetype: preTalk → induction → deepening → therapy → emergence with randomized per-phase durations.
  • SeedLibrary — few-shot, optional. Reads ~/Documents/TrainingCorpus/ label files + SHA-keyed cached transcripts, slices transcripts by labeled phase anchors → real per-phase excerpts in the prompt-cache prefix. Empty dir → zero-shot.
  • ClaudeClient. Thin URLSession wrapper over the Messages API. Key from ANTHROPIC_API_KEY. System prompt + seeds as a cached prefix; one request per phase block.
  • SessionAssembler. Places each block at [start,end), splits text into CorpusSegments, emits one CorpusCase (source:.synthetic, boundaryMode:.exact). Assembler owns placement → truth spans exact.
  • main.swift / CLIOptions. Flags: --out (default Corpus/synthetic/), --ambiguity {low|medium|high} (default low), --count, --seeds <dir>, --model, --dry-run. Each file stamps its generation params.

05Data sources (verified on disk)

For each of the two labeled files in ~/Documents/TrainingCorpus/:

  • Label JSON: phases[] = { phase, startTime, endTime } (ground-truth anchors) + audioDuration, expectedContentType, expectedFrequencyBand.
  • Cached transcript (AnalyzerDataset/cache/transcripts/<sha256>.json): transcription = { fullText, segments[], duration, locale }; segment shape matches AudioTranscriptionSegment.

Joined by audioSHA256 → per-phase real text for seeding (and, later/free, the first Corpus/real/ cases).

07Definition of done (tracer bullet)

  1. CorpusKit extracted; app + IlumionateTests + LumeLabel build green importing it; existing tests still pass.
  2. swift run corpus-gen --dry-run produces one schema-valid Corpus/synthetic/*.json offline (no key, no network).
  3. With ANTHROPIC_API_KEY set, a real run produces a genuine synthetic case.
  4. The existing EvaluationHarnessTests loads and scores the generated file with no harness code change.

08Deferred to follow-up plans

  • Archetype template library (fractionation-heavy, erotic, brainwashing, …).
  • Full ambiguity distribution + bulk generation.
  • Converting the two real labeled files into Corpus/real/ anchored honesty-judge cases.
  • Phase-1 AnalyzerImprover tuning against the synthetic score (parent step 5).

09Constraints / guardrails

  • Generator is dev-time only — never ships; no network in unit tests.
  • ANTHROPIC_API_KEY from environment only — never hardcoded.
  • Watch the "teaching to the test" trap — held-out real corpus stays the safeguard.
  • Never edit features.json unless explicitly asked.
  • Swift 6.2 / modern concurrency; async/await over closures.
  • Build: xcodebuild -project Ilumionate.xcodeproj -scheme Ilumionate build; package: swift build / swift test in Tools/CorpusGenerator/.
