01 — Goal & Identity

A portal, not an app

LumeSync becomes Liminal: the app as a portal to altered states. The UI begins the entrainment before the session does — void backgrounds, slow breathing motion, aurora light. Target qualities: polished, immersive, a little addicting, where the pull comes from sensory delight (craft, motion, glow, haptics) — explicitly not from gamification.

DecisionChoice
IdentityLiminal — cosmic void, breathing aurora, light as protagonist (over Velvet Trance, Neuro, Drift)
The "pull"Sensory delight only — fidget-toy interface quality; no streaks / stats / evolving-world
Color modesDark-only. Appearance setting removed; preferredColorScheme(.dark) enforced
ScopeEverything, phased — 3 phases, each independently shippable
HomeThe Portal — one breathing orb as primary CTA (over browsable "Night Sky")
PlayerPure Void — full-screen light field, whisper UI that auto-fades, swipe-up drawer
ExecutionToken swap first — whole app lands in the new palette on day one

  • Flash-mode colors are part of the light-therapy output path and are not changed by this overhaul.

Typography

  • SF Pro. Ultralight / light at display sizes; regular / semibold only at small sizes.
  • SF Mono for frequency / data readouts — 6.0 HZ · θ — the one place the instrument shows through.
  • Wide tracking on uppercase micro-labels. Dynamic Type respected; minimumScaleFactor only on the orb label.

Motion — three tempos

TempoDurationUse
Breath~5 s loopAmbient: orb breathing, aurora drift. Never stops, never demands attention
Drift0.6–0.8 sTransitions: screen crossfade + slight scale, sheets rise on soft springs
Touch0.15–0.3 sFeedback: glow blooms under fingers, press = scale 0.96 + glow

All Breath-tempo motion freezes to static gradients under accessibilityReduceMotion.

Haptics & sound

  • Keep TranceHaptics, retuned: soft ticks on tab switch; medium thump on "Begin" synced with the orb bloom; optional haptic pulses at hypnosis-phase transitions.
  • No UI sounds — audio belongs to the session.

04 — Screens by Phase

Three waves

Phase 1 — Foundation + identity-defining surfaces

  • Token swap: replace TranceDesignSystem.swift values with the Liminal palette; enforce dark-only; remove appearance picker; flip shadows to glow. Whole app wears the void immediately.
  • Build the kit: AuroraBackground, LumeOrb, LiminalSurface, GlowButton (with previews).
  • Home → The Portal: time-aware greeting; hero LumeOrb as primary CTA. The orb is smart — resume in-progress, else best-fit by time of day (reuses existing BrainwaveCategory ranges). StateChips filter the orb's offer + shelf. One slim "Tonight" shelf; browsing moves to Library.
  • Player → Pure Void: builds on the existing minimal-overlay pattern. Full light field; whisper overlay (name, 6.0 HZ · θ, VoidScrubber) auto-fades after ~4 s; tap recalls; swipe-up = glass drawer (PhaseTimeline, intensity, sync, transitions, track list — nothing lost). Optional phase-transition haptic.
  • Tab bar + MiniPlayer restyled.

Phase 2 — Main tabs

  • Library: structure kept, reskinned. Ghost-tracked headers, LiminalSurface rows with zone-tinted glow dots, glass-capsule search. Session detail + PhaseTimeline preview.
  • Create (Mind Machine): the instrument screen. Luminous frequency dial w/ SF Mono readout, glowing waveform picker, binaural glass deck, live mini light-field preview.
  • Read (TextTrance): RSVP words in light type on voidDeep; sources/setup reskinned. Restyle, not redesign.

Phase 3 — Secondary surfaces

Settings, Audio Library, Analyzer/overlays, profile, streaming — all kit composition. Onboarding is the one real new design: rebuilt around the LumeOrb introducing itself; short, atmospheric, 3 screens. Final step: migrate remaining token call sites and delete TranceDesignSystem.swift.

05 — Architecture & Constraints

Presentation only

Engine boundary — hard rule. This overhaul touches presentation only. LightEngine, FlashController, audio pipeline, analyzers, and session models are untouched. The engine's brightness output path stays byte-identical. This is the main regression risk and is fenced explicitly.
  • Files: Ilumionate/DesignSystem/ — LiminalDesignSystem.swift (tokens) + one file per component. App-target synchronized group; no project-file surgery.
  • Migration: Phase 1 keeps old names (bgPrimary, roseGold…) as deprecated aliases → new tokens, so call sites compile untouched. Phases 2–3 migrate; final phase deletes the Trance system.
  • Performance: ambient motion via scoped TimelineView / .animation on gradient layers — no CADisplayLink competition. Aurora pauses during active flash sessions (light field owns the GPU). Max 2–3 blur layers per screen.
  • Branching: phases land as separate PRs off feature/liminal-ui, each shippable.
06 — Accessibility & Edge Cases

Safe in the dark

  • accessibilityReduceMotion → Breath motion frozen to static gradients.
  • textDim on voidPrimary verified against WCAG AA at body sizes.
  • Glow-only state changes always paired with a shape/weight change (never color alone).
  • Photosensitivity warning flow in the player is safety-critical and stays exactly as-is.
  • Mini-player / overlay / tab-bar stacking keeps current clearance math (tabBarClearance, renamed).
  • Pure Void auto-hide suspends while the drawer is open and whenever VoiceOver is running.
07 — Testing & Verification

Green throughout

  • Existing unit/integration tests stay green (engine untouched ⇒ they should).
  • New: token/contrast sanity tests; view-model tests for smart-orb selection (time-of-day → category); auto-hide timer state tests (timer extracted to a small observable model).
  • Per-phase UI verification: Xcode previews + simulator build (iPhone 17). Instruments only if visible hitching appears.
08 — Out of Scope

What we are not doing

  • Any gamification (streaks, stats, reminders, evolving-world).
  • Light mode / appearance switching.
  • Engine, analysis, audio, or session-format changes.
  • TextTrance functional changes (restyle only).
  • App icon / App Store assets (worth doing later to match Liminal; separate effort).
