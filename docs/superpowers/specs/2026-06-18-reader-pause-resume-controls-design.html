1Problem

The Text Trance reader is deliberately control-free: the player renders only the word stream and the sole interaction is tap-and-hold to end. The session runs a fixed, precomputed schedule with no notion of position — for word in schedule { await sleep(word.duration) }.

  1. No pause. You cannot stop and continue.
  2. No mid-session settings. Changing speed or layers means ending and reconfiguring from setup, which restarts from the beginning.
  3. Coarse speed. A 3-way Slow / Natural / Brisk enum (0.75 / 1.0 / 1.35), chosen once before starting.
  4. No resume after closing. Leaving the reader discards your place entirely.

2Goals & non-goals

Goals

  • In-player pause / resume preserving position (including mid-word remaining time).
  • Live settings mid-session: speed, binaural beats, subliminal flashing, post-handoff light.
  • Finer speed control: a continuous slider with a words-per-minute readout, used in both setup and session.
  • Resume after closing the reader: relaunch a script and continue where you left off.

Non-goals

  • A live reader mini-player (background reading across other tabs). Resume means relaunching at the saved position, not uninterrupted background playback.
  • Position scrubbing / skip within a session. A possible future addition; the resumable driver makes it tractable later.

3Key insight that shapes the design

In TextPacingEngine.schedule, every token becomes exactly one PacedWord regardless of speed or subliminal settings. Subliminal only changes a word's duration (flash vs. normal) and fade; speed only scales effectiveWPM.

The word sequence and count are invariant across speed and subliminal changes. Word index N is always the same word.

So a settings change never requires re-locating position: regenerate the schedule array (same length and order, new durations) and keep reading from the same currentWordIndex. The only setting that would change the word set — the arc — is fixed for a session and is not made live-editable.

5Resumable pacing driver

Replace the fire-and-forget loop with an index-driven, interruptible driver. Session-owned state: currentWordIndex, live speedMultiplier (default 1.0, range 0.5…2.0), isPaused, and the current base schedule.

index = startIndex
while index < schedule.count, !cancelled {
    await waitWhilePaused()                       // suspends while paused
    guard !cancelled else { break }
    let word = schedule[index]
    render(word)                                  // publish currentWord/pivot/phase/fade
    let hold = word.isSubliminal
        ? word.duration                           // flashes are NOT speed-scaled (engine parity)
        : word.duration / speedMultiplier         // readable words scale live with the slider
    let outcome = await holdInterruptibly(hold)   // wakes early on pause or cancel
    switch outcome {
    case .completed:  index += 1; currentWordIndex = index
    case .paused:     continue                     // re-hold the SAME word's remaining time
    case .cancelled:  break
    }
}
  • Remaining-time tracking via an injectable clock (ContinuousClock default). Pause records elapsed; resume holds only the remainder.
  • Speed applies live for readable words; flash durations stay fixed (engine parity). No regen for speed.
  • Subliminal change regenerates schedule and keeps currentWordIndex (sequence invariant).
  • Testable via the injected sleep + clock. begin(from:) supports resumed starts.

6Control surfacing (consistent with the audio player)

  • Reuse PlayerControlsVisibility: visible on entry, auto-hide after idle, tap / swipe-up reveals, swipe-down hides, never auto-hides while the settings drawer is open. Status bar hidden when controls hidden.
  • Clean state: just the anchored word stream.
  • Control panel: pause/play, speed slider + WPM readout, a Settings button (opens the drawer), an explicit End — tap-and-hold-to-end retained.
  • Pause overlay when paused and controls hidden, mirroring PlayerPauseOverlay.

7Speed slider + WPM readout

  • Replaces the setup screen's 3-way SpeedCard; the slider is the single source of truth in setup and session.
  • Range 0.5×–2.0×, default 1.0×.
  • Readout: nominal WPM = 150 × multiplier ("~N wpm", ≈75–300). Honest given per-segment WPM varies.
  • Old presets become optional labeled anchor ticks — cosmetic only.

9Resume-after-close persistence

struct ReaderResumeState {
    let scriptId: String
    let wordIndex: Int
    let settings: PersistedReaderSettings   // arc, speedMultiplier, subliminal*, binaural, light, beat
    let phase: ResumePhase                   // .reading | .handoffTail(elapsed:)
    let scriptContentHash: String            // guards against changed source text
    let savedAt: Date
}
  • Store: ReaderProgressStore (@MainActor @Observable, injectable) persisting a [scriptId: ReaderResumeState] JSON map in application-support. File storage over UserDefaults — testable, and avoids the write race seen with PlaylistStore. Pruned on completion, expires after 30 days.
  • Write points (session-owned): save on pause, on background, on dismiss-while-incomplete; clear on completion.
  • Surfacing: a valid snapshot turns the setup button into Resume (+ Start over); else Begin. Resume calls begin(from: wordIndex) with saved settings.
Staleness guard. The snapshot stores a content hash of the script text. On load, a hash mismatch (likely for imported web reading sources) or an out-of-range index means we discard the resume and start fresh rather than jump to a wrong spot.

Resume into the handoff tail: if closed during the post-handoff light tail, resume restarts the tail from its saved elapsed (the reading is already complete).

11Edge cases & error handling

  • Pause halts word advance and binaural; resume restores both.
  • Pause during the handoff tail stops the tail countdown and light; resume continues the remaining tail.
  • End works from any state including paused: cancel driver, stop layers, dismiss.
  • Backgrounding auto-pauses and persists a snapshot; returning shows controls in the paused state.
  • Subliminal toggle mid-word: current word keeps identity; remaining and future holds use regenerated durations.
  • Resume staleness: content-hash mismatch or out-of-range index → discard, start fresh.
  • Empty / single-word scripts: handled by the loop bound, no special-casing.

12Testing strategy

Swift Testing, using the injected sleep + clock:

  • Driver: pause holds index and re-holds remaining time; resume advances; end-while-paused tears down layers; reaching the end sets isComplete and clears the resume entry.
  • Speed: changing the multiplier alters readable holds but not flash durations.
  • Subliminal: toggling regenerates yet preserves index and current-word identity.
  • Engine invariant: word sequence/count identical across speed and subliminal settings for a given arc.
  • Persistence: round-trip; 30-day expiry pruning; hash-mismatch and out-of-range rejection; completion clears.
  • WPM readout: nominal WPM maps correctly from multiplier.
